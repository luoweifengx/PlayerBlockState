# Player Block Status

按 16×16 区块记录玩家（或组织）的分数，用分数决定区块归属。放置方块、在区块内停留会加分，死亡会扣分。分数达到占领线后，该区块成为领地；长期无人经营则会退回自然。组织用来把多名玩家的分数和领地记到同一账户。

当前版本面向 Minecraft 1.21.5（Fabric）。本仓库是**领土数据库**：内置计分、状态机、组织与指令，并把查询/通知 API 暴露给附属模组。它不改原版刷怪、光照或方块保护。

---

## 需求来源

1. Minecraft 天然按区块管理信息，但只用于存储和世界加载，没有再按区块细化玩法。
2. Minecraft 中许多的建筑行为缺乏功能性，大型建筑本身仅仅只是为了好看，但是历史上的奇观至少都有一些存在的意义，我希望为建筑行为赋予更多的价值
3. 现有领地划分都太过简单粗暴：要么玩家按权限圈地，要么殖民地一类用模组建筑直接控制领地大小。这忽略了玩家自己造出来的东西，游玩体验也偏繁琐。

例如怪物根据光照决定生成。玩家固然可以通过控制光照、放置特殊方块来决定生成情况，但安全区必须保持明亮——本该幽静昏暗的地方，为了安全也不得不插满火把。

本库要做的是：让「这块地是不是你的」由建设与活动长出来，而不是先画框再往里填，去鼓励更多的建设行为。刷怪、氛围、保护等玩法效果，交给附属模组按领土状态自己做。

## 这是什么、给谁用

| 角色 | 用它做什么 |
|------|------------|
| **玩家** | 建造、停留、组织协作，把区块养成领地；用指令改地区名、进界提示、组织。 |
| **服主 / OP** | 改配置阈值；用调试指令查状态、强制改写、导出地图、手动结算或感染。 |
| **附属模组** | 查询区块状态与归属，按领土做刷怪、保护、任务等；也可注册安全区块、结构跟踪、外部组织账户。 |

单独安装本模组时，玩家能看到占领过程、进界提示和组织，**不会**因此少插火把或禁止他人破坏。那些是附属模组的职责。

## 范围

**本库负责**

- 按区块给玩家/组织计分，并用分数决定自然 / 占领 / 边界 / 敌对 / 死亡 / 恶魔等状态
- 脏页延迟结算、敌对边界（感染或传播）、结构 sentinel 与链式认领
- 传送门生成恶魔区块、信标供奉改变扩散
- 内置组织（邀请制、领地并入、合并）
- 进界动作栏提示
- 只读查询、放置/破坏通知、强制改写等对外 API

**本库不负责（范围外）**

- 改变原版怪物生成、光照、难度
- 禁止破坏 / 放置、权限箱、PvP 规则
- 圈地选区 UI、世界地图模组集成（`/pbs map` 只是 OP 调试导出）
- 内置安全群系/地势表（只有 `SafeBiomeChecker` 挂钩，默认全部不安全）
- 完整的外部公会系统（可挂 `OrganizationProvider`，创建/踢人/迁地仍要调用方自己做）

## 计分与占领

每个区块里，玩家或其所在组织各自有一份分数，来源如下：

- **放置方块**：记录放置者（若在组织中则记到组织）。方块仍在则持续计分；被挖掉、炸毁、被活塞推动或其它写入 `setBlockState` 的移除后，对应分数消失。同一格再次放置会覆盖归属，不叠分。
- **停留**：玩家位于该区块时，每隔一段时间增加停留分。停留分只计入**当前结算周期**，结算后清零。换区块或换维度会把停留计时清零；下线不加分。一个周期内能攒到的停留分远低于占领线，**单靠挂机达不到占领**。
- **死亡**：在某区块死亡会扣分。有人分数低到死亡线时，该区块进入死亡态；之后**每次结算**（不是每个游戏日）恢复一部分惩罚。

没有预先圈地。建设与活动使分数升高，超过占领线后区块才被占领。夺取已有主的区块时，挑战者需要明显高于当前主人的分数；内部占领比边界更难夺取。

按默认数值：占领线约等于 **50 个仍存在的玩家方块**。停留只能在本周期里补一小截；方块分会一直留到方块被拆掉。具体阈值见「配置」。

## 区块类型

结算时先根据分数确定区块的基础类型，再根据邻区关系标出边界。边界由邻区计算得出。敌对边界有两种互斥生成模式：默认 **感染** 由错开半拍的抽取链路写入敌对边界与敌对占领；**传播** 则在结算时从边界向外延伸。切换方式见「配置」。

| 类型 | 说明 |
|------|------|
| **自然** | 尚未有人达到占领线。无主，也没有进界提示。 |
| **占领** | 某人（或某组织）的分数超过占领线，且四周仍是自己的占领或边界。这是领地内部。 |
| **边界** | 占领区外侧、邻接「非己方」区块的一圈。地仍属于占领方，但比内部更容易被夺走。 |
| **敌对边界** | 紧挨边界的自然区，不属于任何人。感染模式下由抽取写入；传播模式下从边界再向外延伸（宽度见配置）。 |
| **敌对占领** | 感染把自然/敌对边界进一步写成的敌对占领区块（`HOSTILE`）。不是敌对边界，也不属于玩家。 |
| **安全** | 被标记为不宜争夺的区块（例如特定群系或地势）。不会按建设分占领；若同时有死亡分，仍优先表现为死亡。**状态机已接通，本库不提供默认群系表**；附属模组注册 `SafeBiomeChecker` 后才会出现。 |
| **死亡** | 有人的分数低到死亡线以下。之后每次结算恢复一部分死亡惩罚。 |
| **恶魔** | 地狱门或末地门**被打开/激活**时，传送门方块所在区块变成恶魔区块。每次结算每个恶魔区块有 1% 概率向随机一个四邻扩散。恶魔区块会覆盖任何其它类型，且不能被占领、边界等覆盖。 |

走进有主的占领或边界时，动作栏会显示地区名（见「进界提示」）。自然、敌对边界、敌对占领、安全、死亡、恶魔没有主人，不会弹出进界提示。

## 占领、夺取与退回

- 从未被占领的自然区，分数达到 **占领线** 后变为占领。
- 敌对边界（以及敌对占领）入境占领需要 **占领线 × 边界系数**，不是再攒一份占领线。
- 已经是占领或边界的区块，需所有人的分数都低于 **退回线**，才会放弃主人并退回自然。原先若是敌对边界或敌对占领，分数不够占领时**保持敌对，不会自动消失**。
- 夺取内部占领：挑战者分数至少达到当前主人的 **内部夺取倍率**。
- 夺取边界：至少达到当前主人的 **边界夺取倍率**（与入境敌对边界用同一系数）。
- 边界只出现在占领区真正的外沿（四邻中有一块不是自己的占领或边界）。

倍率与阈值见「配置」。

### 传播模式

敌对边界从玩家边界再向外延伸若干格（切比雪夫距离，默认两格）。不会覆盖他人已占领的地，也不会覆盖恶魔区块或敌对占领。

### 感染模式（默认）

在每个结算周期的**半拍**触发（不是整周期那一拍）。也可用 `/pbs infect`（权限 2）立刻跑一遍。感染**不把变化区块标脏**。

每一拍：

1. 抽取全部玩家边界的 50%。
2. 以抽中的边界为中心，在切比雪夫距离 3（7×7）内处理。
3. **跳过**：该范围内 `OCCUPIED` 格超过 35，且范围内没有恶魔或敌对占领。
4. 范围内已有恶魔或敌对占领时，格子按 **40%** 写成敌对边界；否则 **8%**。只改写自然区；已有占领、边界、死亡、安全、恶魔、敌对占领不会被感染盖掉。
5. 四邻都是敌对（敌对边界 / 敌对占领 / 恶魔）时，敌对边界再升成**敌对占领**。
6. 写成敌对边界后，其四邻的玩家占领降为边界。只传一层，不再向外扩散。

## 脏页与重算

建设、停留、死亡发生时，系统只把该区块标为需要重算（脏页），不会立刻改变区块类型。

重算按结算周期进行（默认约 2.5 分钟一次）。届时只处理脏页：

1. 按当前仍存在的方块、尚未清零的停留分和死亡修正，重算每人/每组织的总分。
2. 用总分决定自然、占领、安全或死亡。
3. 再根据邻区标出边界；传播模式下在这一步派生敌对边界。
4. 停留分清零；死亡态每次结算恢复一部分惩罚。
5. 对全部恶魔区块做一轮扩散（先掷 1% 进入，再随机一个四邻；邻区已是恶魔则不变）。没有脏页的周期仍会做这一步。
6. 状态变过的格子会同步更新**自己的四邻**（看四邻各自的四邻，决定占领/边界）；变成边界时四邻敌对占领降为敌对边界；变成敌对边界时四邻占领降为边界。到此为止，不再向外传。

当前周期的建设要等到这次结算之后，地图上的领地形才会更新。结算进行中如果该区块再次被改动，会留到下一周期再算。没有脏页的周期会跳过分数重算，但仍处理恶魔扩散。

`/pbs set` 等强制改写会立刻写入并标脏；**下一次结算仍按分数重算**，强制结果可能被覆盖。恶魔区块不能被其它状态盖掉。

## 结构认领

结构生成时，被跟踪的结构把模板方块写成 **sentinel** 归属：不计任何人的分数，也不会把自然地形认领进来。

玩家在结构里放置方块后，会从该格沿**六邻**对 sentinel 做分 tick BFS，改写成自己或组织的 UUID。空气、无记录、已有主人的格子停止传播。不是走进结构就自动认领整片。

默认跟踪绝大部分结构，但跳过大体量原版结构（试炼密室、矿井、远古城市、要塞、下界堡垒、堡垒遗迹、林地府邸、海底神殿），避免进档时逐块入队打满服务端。黑名单只跳过 sentinel 捕获；这些区块仍可靠玩家放置/停留分正常占领。附属模组可用 entrypoint 增减跟踪列表。

结构 sentinel 队列只在内存里。若进程被强杀，尚未刷入已加载区块的 sentinel 会丢失。

## 信标供奉与恶魔区块

正在运作的信标（金字塔等级 ≥1）按**当前最高等级**叠加效果；只在一座都不剩时才重置。信标与供奉标志按**全服**计算，不按维度。

| 最高运作信标 | 效果 |
|------|------|
| 1 级 | 扩散进入概率改为 0.1% |
| 2 级 | 停止扩散 |
| 3 级及以上 | 清除全部恶魔区块，并禁止传送门再生成恶魔区块 |
| 全部停止 | 概率回到 1%，允许扩散与生成，并**破坏所有地狱传送门**（不破坏末地门） |

高等级被拆掉但还有低级信标在运作时，不会拆地狱门，只改回剩余最高等级的效果。

## 组织与领土合并

未加入组织时，分数和领地记在玩家个人名下。创建或加入组织后，各维度里原属于该玩家的占领和边界，连同区块内的分数，都会并入组织。之后在组织内的建造和停留，也记到组织账户。

- 一名玩家同时只能加入一个组织。
- **加入**：必须由主人邀请，不能凭组织 UUID 直接加入。邀请不会过期；`/pbs org accept` 接受当前待处理邀请中的第一个。
- **离开**：已并入的领地仍属于组织，个人不能带走。主人须先移交后再离开；最后一名成员离开则解散。
- **组织无人**：最后一名成员离开后，组织记录删除，地仍留在组织账户。
- **合并组织**（权限 2）：被合并组织的成员并入目标组织，各维度里属于前者的领地和分数也改挂到后者名下。目标组织位置不变，范围扩大。

地区名和组织名是分开的。他人走进来时看到的是地区显示名（默认是「某某的领地」），可以另行修改，不会改动玩家 ID 或组织名称。

加入组织后，进界提示以这块地当前的归属为准。地已经属于组织时，他人看到的是组织的地区名；修改个人地区名不会覆盖组织领地上的提示。

组织名与地区名都最长 32 个字符，不能为空，也不能含控制字符。组织名在同一服务器内不可重复。

## 进界提示

走进有主领地时，动作栏可以显示一行提示。每位玩家都可以关闭提示，或选择走进自己领地时使用哪种文案。

### 他人领地

显示对方的公开地区名（默认「玩家名的领地」或「组织名的领地」，可用 `territory` 指令修改）。

### 关闭提示

可用指令关掉，或把配置里的进界显示类型设为关闭（见「配置」）。关闭后，走进任何有主领地都不再显示动作栏提示。重新打开时，使用下面两种显示方式即可。

### 自己的领地

默认显示「自己的领地」。每位玩家可以改成自定义文案，也可以改成与外人看到的公开地区名相同。

指令与配置效果相同：指令会写回配置文件；进服时再读一次配置。键名与取值见「配置」。

- `/pbs territory backmine <文案>` 设置走进自己领地时的文案
- `/pbs territory infotype off` 关闭进界提示
- `/pbs territory infotype sight of me` 使用自定义文案
- `/pbs territory infotype sight of others` 使用公开地区名

纯服务端（客户端未安装本模组）时，进界提示仍使用服务端已记录的偏好；尚未同步则使用默认「自己的领地」。

同一片连续领地内更换区块，只要主人未变，不会重复显示提示。主人发生变化（走出领地，或走进另一处领地）时才会再次显示。

## 指令

玩家常用：

```
/pbs org create <名称>
/pbs org invite <玩家>                 （仅主人）
/pbs org accept
/pbs org deny
/pbs org leave
/pbs org kick <玩家>                   （仅主人）
/pbs org transfer <玩家>               （仅主人，目标须已是成员）
/pbs org info
/pbs org info <组织UUID>               （外人只看到名称、地区名、人数）
/pbs org merge <来源UUID> <目标UUID>   （需权限 2）

/pbs territory info
/pbs territory mine <地区名>           个人地区名（不是玩家名）
/pbs territory org <地区名>            本组织地区名（需组织所有者或 OP）
/pbs territory backmine <文案>
/pbs territory infotype off|sight of me|sight of others
```

OP（权限 2）调试：

```
/pbs query <坐标>                      查看该区块状态与分数
/pbs set here <半径> <状态|keep> [none|uuid|玩家]
/pbs set at <chunkX> <chunkZ> <半径> <状态|keep> [none|uuid|玩家]
/pbs refresh                           立刻跑一轮脏页结算
/pbs infect                            立刻跑一轮感染
/pbs sentinel                          统计脚下区块的 sentinel 格数
/pbs sentinel at <chunkX> <chunkZ>
/pbs map spawn [半径]
/pbs map <玩家> <半径>
/pbs mapplayer ...                     同上，按主人着色
/pbs legend                            地图图例
```

`keep` 表示不改该项；`none` 表示清空归属。半径为切比雪夫距离（正方形），`0` 只改中心一格。

## 配置

全部配置都在 `config/player-block-status.json`。第一次启动会自动写出默认值。上文规则里的「占领线、退回线、结算周期」等都对应下表，不再在各节重复键名。

**领土数值**改完后需要**重启游戏**才生效。

**进界提示**三项进服时会再读一次；也可用 `/pbs territory` 指令改，并写回同一文件。

| 配置键 | 作用 | 默认 | 生效 |
|------|------|------|------|
| `occupationThreshold` | 自然 → 占领所需分数 | 1000 | 重启 |
| `naturalReturnThreshold` | 占领/边界 → 自然（所有人分数都低于此值） | 500 | 重启 |
| `deathThreshold` | 有人分数低至此值则进入死亡态 | −100 | 重启 |
| `blockScorePerBlock` | 每块仍存在的玩家方块得分 | 20 | 重启 |
| `stayScorePerInterval` | 每次停留加分 | 5 | 重启 |
| `stayTickInterval` | 停留加分间隔（游戏 tick） | 100（5 秒） | 重启 |
| `deathPenalty` | 在该区块死亡扣分 | −50 | 重启 |
| `deathRecoveryPerDay` | 死亡态每次结算恢复（键名是历史遗留，不是每个游戏日） | +30 | 重启 |
| `occupationTakeoverMultiplier` | 夺走内部占领：挑战者 ≥ 主人分数 × 此值 | 2.5 | 重启 |
| `borderTakeoverMultiplier` | 夺走边界；亦用于敌对边界/敌对占领入境（占领线 × 此值） | 1.9 | 重启 |
| `hostileBorderMode` | 敌对边界：`infection`（感染）或 `spread`（传播） | infection | 重启 |
| `hostileBorderExtensionChunks` | 传播模式下，从边界向外延伸的切比雪夫格数 | 2 | 重启 |
| `refreshIntervalTicks` | 脏页结算间隔。感染在周期的一半且非整周期时触发 | 3000（约 2.5 分钟） | 重启 |

## 对外库契约

入口类：`luowei.player_block_status.lib.api.PlayerBlockStatusLib`。查询返回不可变视图，不暴露内部存储。仅应在服务端逻辑线程调用。

附属模组通常会用到：

- **查询**：`queryChunk` / `queryChunkState` / `queryChunksInRadius`、组织领地列表、实体占领计数与中心、恶魔区块列表、信标供奉快照、地区显示名
- **通知**：绕过原版 `BlockItem` / `setBlockState` 的模组，应调用 `notifyTrackedBlockPlaced` / `notifyTrackedBlockRemoved`，否则分数会对不上
- **强制改写**：`forceSetChunks`（与 `/pbs set` 同一路径）；写入后标脏，下次结算仍按分数重算
- **组织账户**：`OrganizationProvider` 只负责「这个玩家的分记到哪个 UUID」。默认是外部空档 + 内置组织。挂 FTB 等外部层请用 `ExternalOrganizationBridge.set`，不要整段换成只有内置。成员变动后的迁地要自己调用 `transferPlayerToOrg` / `remapOrganization`
- **安全区块**：`setSafeBiomeChecker`；未设置时没有任何区块会变成安全
- **结构跟踪**：`fabric.mod.json` 声明 `player-block-status:structure_territory` entrypoint，实现 `StructureTerritoryContributor`
- **钩子**：`addBeaconOfferingListener`、`addEntityPollListListener`

导出调试地图、立刻跑感染/结算不在 API 里；请用 OP 指令 `/pbs map`、`/pbs infect`、`/pbs refresh`。

## 持久化

- 区块领土（放置记录、分数、状态、归属）按**维度**存在 chunk attachment / 维度 SavedData
- 组织、玩家显示名、轮询列表存在**全服** SavedData
- 信标供奉与恶魔生成/扩散标志按**全服**计算（主世界 SavedData）
- 结构 sentinel 刷写队列仅内存；正常关服会 `flushAll`，强杀可能丢未刷入的格子

## 进度

本库进度（`player-block-status:home` / `nether_souls` / `beacon_end`）标题与描述用翻译键，附属模组可用同路径 JSON 或语言文件覆盖。

- `home`：玩家（或其所在组织）拥有至少一块占领/边界
- `nether_souls`：第一次打开地狱传送门
- `beacon_end`：全服运作信标最高等级第一次从低于 3 跨到 ≥3

## 调试与性能

Spark / F3 饼图可搜 `pbs.sentinelDrain`、`pbs.structureClaim`、`pbs.sentinelFlushAll`。结构 sentinel 在区块 `CHUNK_LOAD` 时写入已加载的 LevelChunk，tick 只用 `getChunkNow`；超过 10ms 会打 warn，并带 `lookupNs` / `createNs` / `putNs` / `persistNs`。
